# 数据管理模块冻结前整体收口交接包

> 依据当前代码真实状态整理。本文记录本轮冻结前收口调整，不代表产品验收已完成，也不代表已具备直接进入零碳指标管控模块重构的条件。

## 1. 项目当前状态

- 技术栈：Vite + React，JavaScript/JSX，React Router 风格的前端路由与 Context/内存 Store。
- 数据形态：前端 Mock + Context；刷新后以内存初始数据重新加载。
- 真实 API/数据库：当前未接入真实 API、后端服务或数据库。
- 构建：本轮代码调整前已成功执行 `npm run build`；本轮最后一次源码调整后，终端执行器发生环境级启动故障，尚未能重新执行末次构建，不能把旧构建结果当作最终验证结果。
- 数据管理页面：数据总览、企业档案、能源与设施、业务数据；数据问题列表仍保留为隐藏内部路由，能源与设施为正式菜单页面。

## 2. 本轮完成范围

### 数据总览

页面继续使用共享 Context 数据聚合纳管企业、数据项覆盖、正式入库、待处理事项及指标/核心视图风险。支持年度、月份截止期和企业范围筛选；问题摘要与问题列表可跳转至业务数据或隐藏问题列表，并携带期间参数。风险展示已改为“X个核心视图”“X项零碳指标受数据问题影响，共12项指标”。未重做总览视觉和完整产品内容；正式率仍是当前 Mock 记录口径。

### 企业档案

保留企业查询、状态筛选、查看、编辑和新增等现有交互；企业状态可标识待纳管、已纳管、已退出。新纳管企业若没有消费节点，会生成园区责任的“能源接入待完善”数据问题，但不会伪造完整能源节点或业务记录。企业主数据仍来自现有主数据源，尚未接入后端持久化。

### 能源与设施

保留节点、能源流向关系及企业范围筛选、查看/维护交互；节点角色显示改为用户语言，系统编号仅作为弱信息。能源流向不再在页面描述为独立维护月度流量，期间能源量由业务数据承担。能源节点、关系的编辑能力仍是 Mock 级实现，未做图形化能源拓扑重构。

### 业务数据

保留能源、运营、碳排放、零碳专项四个 Tab。支持年度/月度截止期、企业、数据状态、质量状态、来源和关键词筛选；问题记录可打开已有详情弹窗/隐藏能力。生命周期已收口为草稿→提交审核→待审核→正式或退回；正式数据修改会生成下一版本草稿并保留历史。碳排放拆为范围一、范围二，支持 `sourceRecordIds[]`。零碳专项改为屋顶可用面积、光伏面积、绿色建筑、超低能耗建筑、新能源车辆、车辆总量、PCF认证产品、能源诊断等基础事实，不再使用清洁能源比例结果。批量导入仍为前端演示能力，未接真实文件解析和接口。

| PRD对象 | 当前代码对象/状态 |

| Park/SubPark | `park`、`subParks` |
| EnergyNode | `energyNodes` |

| BusinessDataRecord | `businessDataRecords`，统一记录结构 |
| DataItemDefinition | `dataItemDefinitions` |

企业 ID 已作为跨数据管理页面的主要关联键，但仍是前端 Mock 主数据，并非后端稳定主键。当前源码未见 `enterpriseRecords` 作为独立数据管理主模型；`enterprises` 仍作为主数据/兼容导出存在。能源设施未完全消除历史兼容档案。能源关系与期间能源量已在当前数据管理模型中分离：关系在 `EnergyFlowRelation`，期间量在业务记录。业务四域使用同一 `businessDataRecords` 结构和不同数据项定义，但旧模块仍有兼容 Store 投影。`dataStatus` 与 `qualityStatus` 已分开；DataIssue 生成/更新仍是前端显式逻辑，不是后端规则引擎。总览通过 `buildDataOverview` 从共享记录、问题和企业聚合，非另写一套总览静态结果。

## 5. 旧模型与遗留代码

- `energyCarbonData`、`carbonAccountingData`、`operationData`、`indicatorSpecialData`、`renewableFacilities`：仍作为旧模块兼容投影或历史数据保留；并非本轮删除对象。
- `SPECIAL_CLEAN_RATE`：已从当前数据管理定义和新数据生成逻辑移除；旧模块的兼容显示仍可能按旧字段读取，需后续专项清理。
- `constructionTasks`、`taskData`：仍存在于任务相关旧逻辑，未因本轮菜单调整删除。
- IOC 独立业务 Mock：IOC 菜单入口已移除；历史模块/兼容引用仍可能存在，未物理删除文件。
- 旧数据问题页：保留为隐藏路由，供“查看全部数据问题”和下钻使用，不在 Sidebar 显示。
- `enterprises`：仍被主数据和兼容代码引用；`enterpriseRecords` 当前不是主数据管理模型。

## 6. 关键业务链路

1. 企业档案→能源设施：通过 `enterpriseId` 筛选和引用；新纳管无消费节点时只生成 PARK 问题，不自动伪造节点。
2. 企业档案→业务数据：业务记录以 `enterpriseId` 关联企业。
3. 业务数据→总览：在当前内存状态中新增、修改、审核会影响记录统计；覆盖率、正式率和事项会重新计算。风险口径仍是 Mock 简化算法。
4. DataIssue→总览：问题参与待处理事项、受影响企业、核心视图和指标风险；业务记录问题同步 `qualityStatus`。
5. 总览→业务数据：携带 `enterpriseId`、数据项、年度/月度和筛选条件；不保证每种摘要都能精准定位到单条记录。
6. 总览→企业档案：纳管企业范围和企业信息问题可通过企业参数定位。
7. 总览→能源设施：能源节点/流向问题保留能源设施目标；尚未形成完整问题到节点的统一定位协议。
8. 总览→填报任务：详情保留创建填报任务入口；当前没有后端责任判定和完整任务编排，不能宣称所有问题均自动转任务。企业责任路径由已有页面入口承接，园区责任问题不会自动生成企业任务。

## 7. 总览计算逻辑

`buildDataOverview(records, issues, enterpriseRows, year, month, scope)` 先按企业范围和截止月份筛选记录/问题，再通过 `getApplicableDataRequirements` 将年度规则和月度规则展开，计算纳管企业、适用数据项、覆盖率、正式率、待处理事项、受影响核心视图/指标及域状态。月度截止期确实参与计算；当前覆盖率以记录/要求的 Mock 计数口径，正式率以正式记录口径，未实现生产级去重、迟报和版本折算。配置中 IOC 核心视图为 3 个，零碳指标总数固定为 12，属于当前前端配置而非接口返回。

## 8. 能源与设施

`EnergyNode` 当前使用 SOURCE、FACILITY、CONSUMER 等节点角色，消费节点通过企业关联表达；关系使用 `sourceNodeId`、`targetNodeId` 及能源类型、方向、状态等字段。绿电通过能源类型/来源等现有字段表达，未建立独立绿电结算模型。最近流量来自业务记录的期间能源事实，而非能源流向页另维护一套月度事实。当前仍是 Mock，节点/关系与业务记录之间尚未建立后端强一致约束。

## 9. 业务数据

- 能源数据：电、气、热等期间事实，含企业、期间、数值、来源、`dataStatus`、`qualityStatus` 和追溯编号。
- 运营数据：工业产值等运营期间事实，使用同一业务记录结构。
- 碳排放数据：范围一、范围二分开；范围二可通过 `sourceRecordIds[]` 关联电力、热力等多来源。
- 零碳专项：使用园区零碳基础事实，不再使用清洁能源比例结果。

四 Tab 共用统一记录 Store，但定义和业务口径不同；来源追溯、状态筛选、查看/编辑、提交审核、批准、退回、正式版本修订和历史展示已实现为前端交互。批量导入仍为演示能力，空状态和复杂校验未达到生产实现。碳排放活动数据在当前实现中通过来源记录 ID 复用能源事实的引用关系，不是重新维护一套能源活动数据。

## 11. 验证结果

- `npm run build`：本轮最后代码修改后未能重跑；执行器在启动阶段报 `helper_unknown_error`。此前一次相同项目构建成功，不能替代末次构建结论。
- `npm run lint`：项目 `package.json` 未提供该脚本。
- `npm test`：项目未提供该脚本。
- TypeScript：项目主要为 JS/JSX，未配置独立 TypeScript 检查。
- ESLint/控制台/浏览器交互：因执行器故障和未附着浏览器会话，本轮未完成最终浏览器级验证；不能宣称无运行时报错或所有按钮均已点击验证。
- 静态检查已确认：当前数据管理定义不再出现 `SPECIAL_CLEAN_RATE`，菜单不显示 DataIssue，范围二存在多来源记录引用，月份变化会改变聚合结果。

## 13. 下一阶段建议

当前更准确的结论是：具备进入“逐页产品验收”的条件，不具备直接宣称数据管理模块整体冻结，也不应据此直接开始零碳指标管控模块重构。建议依次验收企业档案、能源与设施、业务数据、数据总览，重点确认状态生命周期、问题下钻、企业关联、期间筛选和角色权限；待末次 build 补跑且 P1 口径确认后，再决定是否进入下一模块。
